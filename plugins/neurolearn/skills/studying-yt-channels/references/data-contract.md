# Study data contract

Use this contract when creating or resuming a managed study. All paths below are relative to one study root, use forward slashes, and refer only to that study. UTF-8 JSON is the machine-readable source of state. Extra fields are allowed for topic tags, conditions, speaker attribution, review findings, and the user's request.

The helper is `scripts/study.py` beside this skill. It uses Python's standard library and makes no network or model calls. Its checks establish structural integrity and recorded review coverage, not independent truth or semantic completeness.

## Layout

```text
study.json
catalog.json
INDEX.md
topics.json
final.json
media-ledger.json
videos/VIDEO_ID/record.json
videos/VIDEO_ID/transcripts/ATTEMPT/speech.json
videos/VIDEO_ID/analysis/ATTEMPT.json
videos/VIDEO_ID/evidence/FRAME.jpg
tmp/VIDEO_ID/ATTEMPT/...               # Task-created temporary media only
cleanup-report.json                   # Written after an applied cleanup
```

`catalog.json`, `INDEX.md`, topic files, uncertainty registers, detailed review findings, and rendered chapter outlines are agent-authored. List these and every additional local evidence dependency in `study.json.retained_files`. Retain all transcript versions, including rejected versions, with their real provenance; do not overwrite acquired artifacts to make a check pass. Preserve old analysis versions when publishing a correction and update the active reference.

## Root state

Create the root exclusively through `init` before placing study-owned files in it. It refuses an existing root, creates a UUID and ownership marker (`managed_root`), and starts with `status: in_progress`. Add channel metadata, the inventory snapshot/date window, scope rationale, authorized volume/spending boundary, runtime policies, and progress as additional fields.

```json
{
  "schema_version": 1,
  "study_id": "UUID generated by init",
  "platform": "youtube",
  "channel_id": "UC_CHANNEL_ID",
  "managed_root": "/original/canonical/study/root",
  "selected_video_ids": ["abcdefghijk"],
  "status": "in_progress",
  "active_jobs": [],
  "retained_files": ["INDEX.md", "topics.json"],
  "qualification_notes": []
}
```

Scope IDs are unique 11-character YouTube video IDs. Default selection is all ordinary videos in the request's date/topic boundaries; selection is determined from the catalog, not by the helper. `complete` means no declared source limitations; `qualified_complete` requires nonempty `qualification_notes`. Every selected source needs an explicit outcome before completion. `active_jobs` records work still using study artifacts; completion and cleanup require it to be empty.

The root may be read after relocation, but deletion authority remains tied to its original `managed_root`. The helper does not automatically claim cleanup authority over copied or legacy studies.

## Per-video record

```json
{
  "video_id": "abcdefghijk",
  "url": "https://www.youtube.com/watch?v=abcdefghijk",
  "title": "Publication title",
  "kind": "video",
  "status": "analyzed",
  "transcripts": [{
    "path": "videos/abcdefghijk/transcripts/01/speech.json",
    "sha256": "SHA256 of exact retained bytes",
    "backend": "subtitles"
  }],
  "primary_transcript": "videos/abcdefghijk/transcripts/01/speech.json",
  "analysis": {
    "path": "videos/abcdefghijk/analysis/01.json",
    "sha256": "SHA256 of exact retained analysis bytes"
  }
}
```

Allowed `kind`: `video`, `short`, `stream`; inclusion of nonordinary formats still requires the user's request. Allowed source `status`: `pending`, `analyzed`, `unavailable`, `failed`. A pending/unavailable/failed record needs the identity fields but not transcript/analysis references. Unavailable/failed records require a nonempty `reason` and force Qualified Completion. A pending record prevents completion. Store a pending record immediately after fixing scope so incremental validation can distinguish pending work from a lost source.

The primary transcript is a native NeuroLearn segment JSON object with `backend`, optional finite nonnegative `duration_sec`, and nonempty `segments`, each containing numeric `start`, `end` and string `text`. The recorded backend must match its actual `backend`; `smart` identifies routing and is not actual per-source provenance. Starts are ordered; individual intervals are finite, nonnegative, and not reversed. Other transcript versions retain their hashes and backend fields even when rejected for a recorded quality defect.

## Source analysis and review

```json
{
  "video_id": "abcdefghijk",
  "transcript_path": "videos/abcdefghijk/transcripts/01/speech.json",
  "transcript_sha256": "same primary transcript hash",
  "coverage": [{"first_segment": 0, "last_segment": 1}],
  "claims": [{
    "id": "C1",
    "text": "Attributed source claim with its conditions.",
    "speaker": "Identified speaker or explicit unknown",
    "conditions": [],
    "cautions": [],
    "quantities": [],
    "requires_review": true,
    "evidence": [{"first_segment": 0, "last_segment": 1, "quote": "Exact short excerpt."}]
  }],
  "visuals": [{
    "id": "V1", "start_s": 1, "end_s": 2,
    "status": "sampled_frames",
    "retained_files": ["videos/abcdefghijk/evidence/frame.jpg"]
  }],
  "uncertainties": [],
  "review": {
    "status": "passed",
    "reviewer": "independent reviewer assignment ID",
    "checked_claim_ids": ["C1"],
    "sample_transcript_ranges": [{"first_segment": 0, "last_segment": 1}]
  }
}
```

Segment indexes are zero-based and inclusive. Coverage ranges account for every primary segment exactly once, including off-topic/non-substantive material classified in extra fields. Evidence quotes are literal excerpts from the declared segment range (segment texts joined with one space). Do not silently fix an ASR phrase inside a quotation. Optional `start_s`/`end_s` in evidence must stay within the declared segment range. Meaning, scope, speaker identity, and whether a quotation supports a claim are checked by the reviewer, not by string matching.

Mark practically significant recommendations, quantities, limitations, causal/risk claims and disputed interpretations `requires_review: true`. Every marked claim needs a `checked_claim_ids` review attestation. Source review `status` is `passed`, `qualified`, or `not_selected`; `not_selected` allows neither checked claims nor required claims. Record the reviewer and separately preserve its findings and selection rationale. Sampling includes independently selected original transcript passages to detect omitted thoughts, not merely checks of existing claim records.

Visual status is `pending`, `sampled_frames`, `continuous_clip`, or `unavailable`. Pending is valid only while the study is in progress. Unavailable needs a `reason` and Qualified Completion. Source uncertainties or a qualified source-review outcome also require Qualified Completion. Retained frames/crops belong outside `tmp/`; the helper verifies their presence. Record exact observed sample times, source URL, candidate/observed interval distinction, and method in additional fields. A sampled-frame status never certifies continuous viewing.

## Final conclusions

```json
{
  "conclusions": [{
    "id": "F1", "text": "A material final conclusion.",
    "evidence": [{"video_id": "abcdefghijk", "claim_id": "C1", "quote": "Exact short excerpt."}]
  }],
  "review": {
    "status": "passed", "reviewer": "independent final reviewer ID",
    "checked_conclusion_ids": ["F1"]
  }
}
```

Every conclusion has source evidence; its quote must match an evidence quote of the linked claim, not unrelated text from the same video. A narrower quote can be added to the source claim first and reviewed there. Every final conclusion ID appears in the independent final-review attestation. A qualified final review requires Qualified Completion.

The readable result also contains in-text YouTube timestamp links, explicit interval ranges, and short supporting quotations. Preserve the conclusion-to-claim-to-transcript chain above; multiple-source interpretations keep all material premises and relevant exceptions. List readable outputs and their additional local image/file dependencies in `retained_files`; the validator checks declared dependencies, not arbitrary links inside every free-form document. Transcript-derived quotations are not audio-verified unless such a check actually happened.

## Helper commands

Use `python3` on macOS/Linux or the verified Python launcher on Windows. Substitute the actual skill directory and study path; one controller owns state writes.

```bash
python3 <skill>/scripts/study.py init <new-study-root> --channel-id UC_CHANNEL_ID --video-id abcdefghijk
```

```bash
python3 <skill>/scripts/study.py validate <study-root>
```

```bash
python3 <skill>/scripts/study.py register-media <study-root> --video-id abcdefghijk --path tmp/abcdefghijk/01/source.mp4 --kind video
```

```bash
python3 <skill>/scripts/study.py cleanup <study-root>
```

```bash
python3 <skill>/scripts/study.py cleanup <study-root> --apply
```

`validate` is read-only: exit 0 means structural checks passed, exit 1 reports validation errors. Other refused operations return exit 2. JSON output always states the boundary of validation; recorded reviewer attestations are not independent proof that a review took place or was correct.

## Ownership and cleanup

Only register temporary files created by this study after exclusive initialization. `register-media` records the study/video identity, exact relative path, kind, SHA256, size, mtime, device/inode identity and link count in `media-ledger.json`. Registration does not perform a full-corpus scan and is not by itself permission to delete. The supported kinds are `video`, `audio`, `unused_frame`, `download`.

Cleanup previews by default. Apply requires a complete/qualified-complete root, no active jobs, valid final evidence/review records, and successful read-only validation before the first deletion. Only individually registered media/download suffixes under `tmp/VIDEO_ID/` are candidates. All candidates are checked before any removal; one bad candidate blocks the operation. Symlink/junction components, hardlinks, traversal/outside paths, mismatched ownership, changed content/identity, retained dependencies, unknown file types, and unregistered files are not deleted. There is no recursive removal or whole-cache pruning.

Apply and registration use an exclusive `.study.lock`; all other study writers must be stopped before cleanup. A leftover lock requires inspection, not automatic removal. The ledger is atomically updated after each successful deletion, and `cleanup-report.json` records actual removals and bytes freed. Retained references are checked again afterward. If execution is interrupted between deletion and ledger update, the next run safely refuses the missing present-file entry; inspect and reconcile that history rather than auto-claiming deletion success. Historical removed paths remain in the ledger and are not live evidence dependencies.

This helper is intentionally not a sandbox against a hostile process concurrently replacing directories. It requires the agreed single-owner, quiescent cleanup stage. It never migrates or cleans an older research folder merely because it contains similar filenames.
